# Generator RL implementation

New files implement DDPO-SF with a Gaussian DDIM denoising policy for the actual pretrained InstructPix2Pix UNet attention LoRA. The Phase2 native Euler unsupported interface is intentionally preserved as historical evidence. This method changes the scheduler explicitly; it is not a claim that native Euler has been validated.

`diffusion_policy.py` preserves unscaled VAE source-image mode, instruction/empty/empty text conditions, source/source/zero image conditions and the native guidance formula. FP32 sampled latent actions/noise have a defined continuous Gaussian density. Frozen base UNet/VAE/text computation is BF16, adapter master parameters FP32. Numerical variants and failures are retained in the assumption ledger; later variants isolate FP32 A/B computation and sequential CFG. No target VLM parameters enter the optimizer.

`diffusion_trajectory.py` defines DDIM epsilon means, positive variances, detached-action Normal log density and exact model/config/version association. `diffusion_rl_trainer.py` makes one on-policy pass, accumulates one trajectory at a time and all ten stochastic denoising steps, clips generator gradients and calls AdamW once. Fixed coordinate/time averaging scales the terminal expected-reward score gradient by a constant. No denoising target or supervised MSE enters this objective.

Reward uses preserved Phase2 safe components and weights S=1,A=.5,D=.2,C=.1,U=1, clipping [-1,1.5]. Unknown natural-image semantics retain the uncertainty penalty; proxy agreement is not verified semantics. C=10/30 is a fixed denoising-step reference, with real sampling/judging/allocation costs recorded separately. Advantage is individual reward with zero baseline and scale one; batch mean/variance are reports, not whitening statistics.

Every update invalidates prior trajectories. Behavior adapter snapshots, FP32 states/actions/noise, log probabilities, timestep sequences, seed, original sample IDs, Q/answers, reward components, model revision and full contract are saved. No KL reference is required by this score-function estimator. The old behavior policy is checked for provenance/replay; it is not a PPO importance denominator.

Checkpoint state includes adapter, AdamW moments/step, constant LR scheduler, consumed IDs, policy version, model/data/config contract, Python/NumPy/Torch/CUDA RNG. Reload into a fresh pretrained pipeline checks actual continuation. Exact state restoration is distinguished from identical floating-point backward continuation; failed exact checks remain FAIL and are listed separately. See smoke/failure reports for executed readiness.

Accounting distinguishes source images, trajectories, ten transitions per trajectory, sequential three-branch UNet API calls, accumulated source microbatches, per-transition backward calls, optimizer updates and diagnostic replay. Internal activation-checkpoint recomputation calls are not included in the API-call counter; full Slurm cost includes them.
