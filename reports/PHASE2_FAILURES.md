# Phase 2 failures and fixes

1. Initial environment inspection found no diffusers package in the Qwen environment. This was an expected missing component; created a separate `.venv-editor` over the existing CUDA base and installed pinned Diffusers/PEFT dependencies. Original `.venv` remains unchanged.
2. Generator job 86293 failed after supervised updates, frozen-weight verification and fresh-model training-state continuation checks, at the public Diffusers adapter export/reload interface. Error: `When using the offline mode, you must specify a weight_name.` Fixed `load_lora_weights` to supply `pytorch_lora_weights.safetensors` and `local_files_only=True`. Original failed run, adapter checkpoints, tensor evidence and logs remain immutable. A new full generator smoke will verify the fix; no partial execution is counted as a full training PASS.

All Phase 2 failed allocation time is charged to the 7200 GPU-second budget.

3. Retry 86299 reached fresh-model inference reload but failed the exact resumed-next-step parameter comparison (no OOM). This is not reported as a full PASS. Added persistent original/resumed loss, per-tensor max difference, optimizer/scheduler equality and resumed checkpoint diagnostics before the assertion. The next bounded diagnostic run will measure the divergence before selecting a repair; no tolerance is silently relaxed.

4. Diagnostic 86301 demonstrated exact next-step replay: max adapter difference 0, identical loss 0.004338245041435584, optimizer and scheduler equal. It then failed the public export pixel check (max difference 74; predeclared tolerance 2). Root cause independently confirmed in pinned Diffusers source: exporting A/B weights without PEFT metadata loses lora_alpha=16, so reload defaults alpha=rank=8 (scale 1 instead of 2). Export now preserves `unet_lora_adapter_metadata`, and fresh loading asserts rank/alpha before comparing pixels. No tolerance was relaxed. The earlier 86299 exact failure remains preserved; no invented root cause is assigned to it.

5. Job 86302 measured the repeated exact-resume failure: maximum adapter difference 4.410139808896929e-8, identical forward loss, scheduler equal, AdamW state not bitwise equal. This is small floating-point divergence, not an OOM or zero-gradient failure. To isolate fused-attention backward numerical behavior, selected explicit math SDPA for generator inference/training and kept exact replay assertions. This changes the recorded generator execution backend; it is not a tolerance relaxation or proof of the precise kernel-level cause.

6. Math-backend diagnostic 86303 failed during activation-checkpoint recomputation: forward was inside math SDPA but backward recomputation occurred after that context exited, changing the saved/recomputed tensor metadata. Wrapped the entire update (including backward) in the same math-SDPA context. This is a diagnosed context-lifetime bug introduced by the numerical isolation change; no OOM occurred and no acceptance threshold changed.

7. Job 86304 passed exact math-backend next-step/optimizer/scheduler replay and rank/alpha loading, then public-export pixels differed by 39. Pinned PEFT source independently confirmed that public attachment casts new A/B parameters to the base dtype, rounding saved FP32 adapter values to BF16. Casting them back afterward cannot recover the original values. Fixed by temporarily attaching with FP32 UNet, then restoring only frozen base tensors to BF16 and retaining exact FP32 adapters; inference adapters are explicitly frozen. Added exact public A/B tensor equality/dtype checks before the unchanged pixel tolerance. No claim that this unexplained discrepancy was harmless is made.

8. Automatic approval review rejected the proposed next 10-minute GPU job, stating that the sum of requested wall limits appeared to exceed the authorized 2-hour budget. No action executed on that rejected call. A read-only `sacct -X` ledger showed all nine prior jobs terminal, actual cumulative allocation 450 seconds (0.125 GPU-hours), empty queue and 6750 seconds remaining. An evidence-based retry of the same submission, with its full 600-second maximum explicitly within budget, was approved; job 86306 completed in 48 seconds. No alternate submission route or budget bypass was used.

9. Corrected job 86306 passed all generator assertions: actual adapter update, all frozen weights unchanged, exact training-state inference and resumed next-step/optimizer/scheduler, public FP32 A/B values and rank/alpha preserved, and public generated pixel max difference 0. Failed prior runs/checkpoints remain retained. The earlier fused-attention numerical issue is reported, not retroactively erased.
