# Frozen preparation protocol

- VQAv2 preliminary subsets contain 1000 train, 200 validation and 300 internal test questions. Split image pools first with seed 42, then sample approximately by answer type. Official annotations come from the [VQA download page](https://visualqa.org/download.html); dataset terms remain applicable. Download only selected COCO images. Source archives, image hashes, split IDs and distributions are retained.
- Test is held out of optimizer updates and controller revision selection. Training code checks every record has `split=train`. RSI requires the same validation identity and `split=validation`. Baseline smoke evaluates ten validation samples, not test, for this preparation task. Synthetic oracle wiring uses its separately generated test fixture.
- Qwen clean evaluation is frozen; image-only augmentations leave question text and ground truth intact. No poisoned checkpoints are created. Authorized pre-existing security fixtures, if later supplied, are read by independent offline evaluation only.
- Full experiment IDs are UTC timestamp + random UUID segment + descriptive tag, allocated exclusively. Seeds/configs are separate from IDs. Each change creates a new run; never replace an older config or checkpoint. Resume continuation occurs from a trusted checkpoint in a new run with parent provenance.
- Checkpoints include policy, AdamW, scheduler, step, config, Python/NumPy/Torch/CUDA RNG states. Smoke tests compare the next resumed step, optimizer and scheduler exactly on one device. Model weights and data remain outside Git; source and configs are committed locally on both systems. No remote publication is requested.
- Resume requires reconstructing matching config/reward/editor/evaluator/device/data/batch schedule; a mismatch is rejected before state loading. The fixed smoke always runs three updates; it rejects another total_updates value. Full GPU acceptance returns nonzero if requested model/data checks are blocked.
- Planned arms are fixed configuration, standard RL, RL + adaptive configuration and RL + RSI. Future comparisons must freeze equal total GPU-hour/model-call budgets including proposals, failed trials, validation and loading; log rejected outcomes. Current toy controller scores do not instantiate this scientific comparison.
- Smoke acceptance is functional: finite rewards/gradients, parameter-change/freeze checks, checkpoint replay, fixture correctness, deterministic generation, split disjointness and independent log allocation. It does not establish robustness, attack success, RSI superiority or generalization.
- Failures and remedies are retained, including failed runs. Project scratch directories are uniquely named and checked before removal. Weights, unique evidence and unrelated histories are never routine cleanup targets.
